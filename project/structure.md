# Структура проекта

- `app/` — Flask API, расчёты, нормализация источников, авторизация, фоновые задачи и статические ресурсы. Точка входа web: `python -m app.server`; отдельного обновляющего процесса: `python -m app.worker`.
- `frontend/` — React/Vite интерфейс CharterStats. Исходники в `frontend/src/`; сборка через `npm run build:ui` попадает в статические ресурсы приложения.
- Форма входа находится в `app/templates/charter_login.html`. Авторизованный интерфейс получает рабочий набор и пользователя одним запросом `GET /api/charter?view=workspace`; CSRF передаётся в заголовке ответа. Графики загружаются отдельным модулем. Vite-файлы с хешем кэшируются, а документы и API используют `no-store`.
- Адреса разделов расположены в корне, например `/data`, `/calendar` и `/users`. Flask перенаправляет прежние ссылки `/charter/<раздел>` на адреса в корне. API и ресурсы сборки сохраняют свои пути.
- Смена периода и переходы между разделами пересчитывают отчёты на уже полученном рабочем наборе. В `frontend/src/model.js` календарные строки индексируются по сущности и дате, рейтинги используют общий индекс и обходы по выбранному диапазону. Интерфейс считает детализацию для открытого раздела, для значка отклонений достаточно счётчика.
- `deploy/` — проверка перед запуском, резервное копирование и шаблоны systemd/nginx. `requirements*.txt`, `package*.json` и lock-файлы — рабочие файлы зависимостей.
- `scripts/` — локальные вспомогательные команды; `tests/` — Python и JavaScript проверки.
- `data/` — локальные рабочие и архивные данные, включая SQLite и настройки подключений. Этот каталог исключён из Git. `.local/` и `work/` содержат локальные артефакты и также исключены из Git.
- `project/` — только актуальная тематическая документация; `AGENTS.md` в корне служит указателем.

На VPS сайт работает из `/opt/fleet-analytics/current` (ссылка на release), данные находятся отдельно в `/var/lib/fleet-analytics`. Службы `fleet-web` и `fleet-worker` запускают web и обновление; конфигурация окружения находится в `/etc/fleet-analytics/environment`. Локальная база после переноса является архивной: не запускать для неё второй фоновый опрос и не копировать поверх серверных данных.

Новый release и документация на VPS не появляются автоматически от локального изменения или push. Перед публикацией сверяйте фактическую версию, состояние служб и сохранность данных.

`npm run preview:live` собирает локальный интерфейс в `.local/charter-live-ui` и запускает его на `http://127.0.0.1:8777`. Вход выполняется рабочей учётной записью. Предпросмотр передаёт разрешённые запросы чтения в рабочий API через HTTPS и хранит сессию в памяти процесса. Запросы изменения данных блокируются локально.

Для HTTPS-виртуального хоста CharterStats предусмотрен gzip для статических ресурсов и ответа `/api/charter`. Прокси передаёт тот же Host и HTTPS-схему в обоих маршрутах.

История назначений водителей картам Роснефти хранится в таблице `rosneft_driver_assignments` в SQLite. Её обновляет синхронизация Роснефти, а ручные назначения сохраняет API раздела ГСМ.

Автоматическая догрузка мониторинга использует суточные подтверждения в `refresh-coverage.json` и время повторных попыток в задаче `monitoring:history` файла `refresh-auto.json`. API `POST /api/charter/deviations/export` формирует XLSX из выбранных строк интерфейса и не меняет рабочие данные.

Управление учётными записями обслуживают `POST /api/users`, `PUT /api/users/<id>` и `DELETE /api/users/<id>`. При обновлении приложения в таблицу `users` добавляется поле версии сеанса. Удалённые идентификаторы повторно не выдаются, чтобы сохранить ссылки в истории действий.

Переопределения полномочий хранятся в `users.permissions`. Базовые права и серверные проверки определены в `app/permissions.py`. `GET /api/users/permissions` возвращает справочник полномочий для карточки сотрудника, а рабочий набор возвращает действующие права текущего пользователя. В `audit` хранятся имя исполнителя и изменения полей. `GET /api/audit` возвращает список событий, `GET /api/audit/<id>` загружает изменения выбранного события. Изменения записываются в той же транзакции, что и правка данных в SQLite.

Явные отметки в `users.permissions` хранятся и тогда, когда совпадают со значением по роли. При смене роли сервер применяет новые значения только к полномочиям без явной отметки.

Формы заявок, полноты, расходов, справочников, тарифов и привязок карт находятся в `frontend/src/record-editors.jsx`. Они используют общие API/session, таблицы и боковые панели основного интерфейса. `GET /api/records/<id>` загружает полную рабочую заявку с версией для редактирования без расширения сокращённого рабочего набора. Архивные строки Excel и удалённые заявки в этот маршрут не входят. Проверки всех 15 полномочий для логиста и наблюдателя находятся в `tests/test_permission_workflows.py`.
