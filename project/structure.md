# Структура проекта

- `app/` — Flask API, расчёты, нормализация источников, авторизация, фоновые задачи и статические ресурсы. Точка входа web: `python -m app.server`; отдельного обновляющего процесса: `python -m app.worker`.
- `frontend/` — React/Vite интерфейс CharterStats. Исходники в `frontend/src/`; сборка через `npm run build:ui` попадает в статические ресурсы приложения.
- `deploy/` — проверка перед запуском, резервное копирование и шаблоны systemd/nginx. `requirements*.txt`, `package*.json` и lock-файлы — рабочие файлы зависимостей.
- `scripts/` — локальные вспомогательные команды; `tests/` — Python и JavaScript проверки.
- `data/` — локальные рабочие и архивные данные, включая SQLite и настройки подключений. Этот каталог исключён из Git. `.local/` и `work/` содержат локальные артефакты и также исключены из Git.
- `project/` — только актуальная тематическая документация; `AGENTS.md` в корне служит указателем.

На VPS сайт работает из `/opt/fleet-analytics/current` (ссылка на release), данные находятся отдельно в `/var/lib/fleet-analytics`. Службы `fleet-web` и `fleet-worker` запускают web и обновление; конфигурация окружения находится в `/etc/fleet-analytics/environment`. Локальная база после переноса является архивной: не запускать для неё второй фоновый опрос и не копировать поверх серверных данных.

Новый release и документация на VPS не появляются автоматически от локального изменения или push. Перед публикацией сверяйте фактическую версию, состояние служб и сохранность данных.
