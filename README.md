## Самостоятельная установка и тестовая среда

Для отдельной установки нужны Python 3.12+, `python3 -m venv .venv` и `.venv/bin/pip install -r requirements-lock.txt`. Первый импорт требует обе исходные книги: задайте `FLEET_EXCEL_DIR` или отдельно `FLEET_STATISTICS_XLSX` и `FLEET_PLANNER_XLSX`. Альтернатива — приватный `.local/excel-sources.json`: `{"directory":"/абсолютный/путь/к/книгам"}` (либо поля `statistics` и `planner`). Относительные пути JSON разрешаются от файла настройки. Заполненная база запускается без книг. Книги и реквизиты в Git не входят.

Для проверки в отдельном каталоге данных (переменные задаются **до** импорта `app.server`):

```sh
FLEET_DATA="$(mktemp -d)" FLEET_SCHEDULER=disabled .venv/bin/python -m pytest -q
```

Для новой самостоятельной локальной установки `./start.sh` запускает сервер на loopback `http://127.0.0.1:8765`. Укажите собственный `FLEET_DATA`; эта команда не предназначена для запуска архивной рабочей копии после переноса. Для изолированного ручного UI-теста дополнительно отключите scheduler и выберите свободный порт. При новой установке начальная памятка входа хранится в ее закрытом каталоге данных; существующие рабочие доступы не заменяются.

Браузерные проверки используют отдельный Chromium, фиктивный домен и перехваченные API, без рабочей базы и поставщиков. Node-зависимости закреплены в lockfile:

```sh
npm ci
npx playwright install chromium
npm test
npm run test:browser
npm run test:browser:failure-probe
```

[Протокол и границы браузерной проверки](docs/acceptance-20261102/sidebar.md) · [Матрица R01–R30 / A1–A10](docs/acceptance-20261102/customer-matrix.md). Браузер нужен только в среде проверки, не на рабочем VPS.

## Интерфейс и обновление 29 октября

[Руководство для заказчика](docs/Руководство-заказчика.md) · [Сверка всех Excel-таблиц и записи заказчика](docs/ui-ux-20261029/EXCEL-REQUIREMENTS.md) · [Результат UI/UX-проверки](docs/ui-ux-20261029/RESULT.md).

- «Данные» содержат заявки, показания спутника, операции обоих топливных поставщиков и справочники. «Подключения» содержат состояние источников и ссылки к данным.
- «Качество данных» разделяет исправимые записи, ограничения API и исторические замечания импорта. Пустые карты, расходы и периоды объясняют, что заполнить и на что это влияет.
- Календарь планировщика переключается между маршрутами и автомобилями. Встроенная инструкция находится в «Помощь → Как пользоваться».
- Работающий `./start.sh` запускает цикл каждые 300 секунд: текущий месяц до сегодняшнего дня по МСК, независимые очереди источников и догрузка пропущенных завершённых дней. История ТТ и пропуски ID дополнительно проверяются раз в сутки. Открытая вкладка не нужна. Для серверного автозапуска и восстановления процесса предназначены отдельные службы, описанные ниже; локальный `start.sh` не заменяет их.
- Общая кнопка руководителя получает данные из API за применённый период (1–31 день); наблюдателю и логисту перечитывает рабочую базу. Источник с ошибкой отмечается отдельно. Долгое задание не накладывается на следующее.
- При вводе в форму или открытой карточке обновление экрана откладывается. Поиск, сортировка и прокрутка таблиц сохраняются. Просмотр августа на страницах топлива остаётся августом после автоматического обновления октября.
- Excel автоматически не перечитывается. Фактические привязки карт, полноту периодов и дополнительные расходы должен заполнить ответственный сотрудник; приложение не выдумывает их.

## Возможности

- Статистика по машинам, водителям, их сочетанию, клиентам, типам транспорта, исполнителям, датам и видам начислений; произвольный период; CSV и детализация заявок.
- Календарь автомобилей/водителей: работа и ручные статусы. Статусы не превращаются в заявки.
- Планировщик: реальные маршруты, ставки, назначение на период и дни недели, список и календарь, расчёт выплат своим водителям/партнёрам.
- План–факт по рейсам; отсутствие источника обозначено «—».
- Сверка ТТ–спутник по машине и дате начала, с отсутствующими данными и детализацией.
- Справочники и повторный импорт Excel без умножения строк. Предыдущие снимки сохраняются; ручные записи остаются.
- Роли руководителя, логиста и наблюдателя; машины логиста, журнал действий, серверные проверки доступа и CSRF.
- Диагностика подключений. **Нефтьмагистраль подключена: транзакции загружаются через API по кнопке за выбранный период.** **Роснефть подключена: карты, операции, скидки, возвраты и CSV; обновление по кнопке за период до 31 дня.** **ГЛОНАССсофт подключён: объекты, последние показания и история пробега, моточасов и топлива.** История загружается небольшими суточными порциями с продолжением после прерывания и используется в статистике и сверке. **ТрансТрейд подключён: серверное чтение заявок, обновление по кнопке за период до 31 дня, история изменений и защита от дублей.** Подробности в `docs/Подключения.md`.

## Самостоятельная работа на сервере — 30 октября

[Результат и проверки](docs/server-autonomy-20261030/RESULT.md) · [Установка на Linux](docs/server-autonomy-20261030/DEPLOYMENT.md) · [Предупреждения](docs/server-autonomy-20261030/ALERTS.md).

Сайт и загрузчик работают отдельными процессами. Источники опрашиваются каждые 300 секунд по сохранённому расписанию, ошибки одного не задерживают остальные. Прерванная работа продолжается после запуска без повторного добавления записей. Завершённые дни догружаются от старейшего пропуска: до семи дней за порцию для ТТ и топлива, один день для спутника. Последняя неделя топлива и последние сутки спутника перечитываются для поздних данных. Отметка успешного чтения API не доказывает полноту его выдачи.

Подготовлены службы systemd с автозапуском, перезапуском и контролем зависаний, а также отдельный таймер проверки остановки загрузчика. `/healthz` проверяет доступность сайта и загрузчика; ошибки отдельных API видны отдельно в приложении. При задержке источника более 15 минут появляется предупреждение; повторная попытка не считается восстановлением. Внешний канал по умолчанию выключен и ещё не выбран. На этом этапе (30 октября) службы на удалённом сервере еще не устанавливались; последующая публикация 2 ноября описана в [протоколе VPS](docs/deploy-20261102/DEPLOYMENT.md).
