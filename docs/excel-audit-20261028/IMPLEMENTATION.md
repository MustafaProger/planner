## Где вводить данные

| Данные | Раздел и операции |
|---|---|
| Автомобили, ресурсы партнёров, водители | Справочники: добавление, изменение, архив, варианты названия; явное объединение одного объекта |
| Компании, клиенты, исполнители, типы транспорта, способы расчёта, причины статусов | Отдельные редактируемые справочники |
| Маршруты и ставки | Справочники → Маршруты → Тарифы; дата начала действия, выручка, выплаты своим водителям/партнёрам, пробег, часы, почасовые ставки |
| План | Планировщик: период, дни недели, ресурс, водитель, маршрут, состояние, номер отдельной смены; редактирование импортированных и ручных назначений |
| Факт до подключения ТТ | Заявки ТрансТрейд → Ввести заявку. Номер, точные начало/конец, справочники, способы расчёта, суммы, км и категория. Локальные заявки можно редактировать. Они не отправляются в ТТ |
| Категория импортированной заявки | Изменить в таблице заявок / Проверке записей. Исходные суммы сохраняются. Поправка категории сохраняется при повторном импорте |
| Простой и статус | Календарь: автомобиль / водитель, дата или период, причина, комментарий; изменение и удаление статуса |
| Топливная карта и машина | Привязки топливных карт: провайдер, номер карты, машина, даты действия. Пересечение дат одной карты запрещено |
| Прочие расходы | Расходы: машина, дата, вид, сумма, комментарий; изменение и удаление |
| Подтверждение полноты | Полнота периодов: план / фактические заявки, даты, явное подтверждение всех машин за весь период |

Справочники и записи связаны постоянными идентификаторами. Переименование сохраняет связи. Архивирование сохраняет историю. Руководитель ведёт справочники, тарифы, привязки и расходы; логист вводит и меняет планы, локальные заявки и статусы в рамках назначенных машин; наблюдатель читает. Проверки прав и CSRF выполняются сервером. Одновременные изменения форм защищены проверкой версии записи.

Тариф на каждый день периода определяется по дате начала его действия. Сохранённое назначение содержит собственные суммы: новый тариф не пересчитывает прошлые назначения. При смене даты, маршрута или водителя назначение получает соответствующий тариф. Итоговые ставки задаются явно; почасовые значения справочные, исключения Excel не заменяются предполагаемой формулой. Тариф на уже занятую дату повторно не создаётся.

## Исправления расчётов

- 158 строк «нет маршрута» сохранены с отдельным состоянием и исключены из числа рейсов, километров и часов плана. 88 назначений с отсутствующим ресурсом/водителем сохранены как неназначенная работа.
- Два одинаковых назначения `Логист!25` и `Логист!35` помечены для проверки. Обе спорные записи временно исключены из итогов. Если это два действительных рейса — присвоить разные номера смен. Если один лишний — отменить его. Автоматически выбирать одну строку нельзя.
- Отклонения план–факт выводятся только при подтверждённой полноте обоих источников за весь выбранный период и отсутствии спорных/неназначенных планов. Без подтверждения отсутствие записей остаётся пропуском. Факты без плана видны отдельно.
- У А258ОА797 за июль–сентябрь остаются план 547 658 ₽ и факт 369 170 ₽, но недостоверное отклонение −178 488 ₽ больше не выводится. См. [скриншот](comparison-fixed.png).
- Марка и компания автомобиля разделены. Причины `ПростойСервис` / `Сервис` нормализованы. Сводка считает уникальные дни и показывает пересечения работы со статусом.
- Повторный импорт накапливает периоды, не заменяет рабочую историю; сохраняет исправления и ставки планов. Ручные записи, позже попавшие в Excel, распознаются по деловому ключу. Импорт не служит массовым редактором существующего плана — изменённые назначения исправляются в приложении.
- История топливных операций накапливается по успешно загруженным периодам. Повторная загрузка заменяет только свой интервал. Обслуживание 11 учитывается как покупка, возврат 24 вычитается; прочие движения не приписываются расходам. Объём газа/топлива — объём покупки, не расход двигателя.

## Отчёты

- Сводка плана: автомобиль, водитель, маршрут, компания, день, месяц, квартал и год; выручка, выплаты, доля выплат, рейсы, дни, км и часы.
- Календарь маршрутов: маршрут × дата, внутри ячейки машина, водитель, состояние и переход к редактированию.
- Статистика факта: добавлены месяцы, кварталы, годы, способы расчёта клиента/исполнителя и процент выплат от выручки.
- Работа и простои: машины / водители, уникальные рабочие дни, дни статусов, причины, пересечения, клиенты и количество рейсов.
- Экономика: выручка, выплаты, покупки по привязанным картам, прочие расходы, остаток после известных затрат. Это не чистая прибыль: отчёт явно показывает неполноту привязок и неразобранные движения.
- Спутниковые записи: исходные интервалы, одометр начала/конца, движение, стоянка, холостой ход и адреса; машины без заявок также видны. Суточные API-показатели и пропуски остаются в сверке.
- Проверка записей: спорные повторы, неназначенная работа, отрицательные/безмашинные «рейсы», служебные обозначения. Для фактической классификации 51868 и других неоднозначных строк есть управляемое исправление, без изменения денежных сумм.

## Что требуется заполнить реальными решениями

Структура готова для ежедневного ввода без Excel. Исходные книги остаются источником первичного заполнения и необязательного импорта. Для достоверных итогов нужно назначить ресурсы 88 незавершённым планам, разобрать два возможных дубля и спорные категории факта, указать реальные привязки топливных карт и подтверждённые расходы. 316 имеющихся топливных операций пока не имеют привязок к машинам; девять движений счёта не классифицированы как покупки. Их нельзя распределить по предположению.

API ТрансТрейда не подключён. Пока доступны исходные заявки, локальный ввод и импорт. Сопоставление спутника с отдельным ночным рейсом и распределение фактического расхода на заявки не выдумываются из суточных показаний. Согласованной формулы налогов и полной себестоимости в материалах нет; отчёт показывает остаток после известных затрат. Эти ограничения относятся к исходным сведениям и интеграции, а не к отсутствию форм для ввода.

Для резервирования сохранять весь закрытый каталог `data/`, включая SQLite, историю интеграций и ключ сессии. Для возврата до миграции сначала остановить сервер, сохранить текущую базу отдельно и использовать проверенную копию вместе с совместимой предыдущей версией кода. Не заменять текущую базу старой копией после начала новой работы без сверки введённых записей.
