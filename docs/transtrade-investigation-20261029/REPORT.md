# Проверка возможностей TransTrade API — 29.10.2026

## Вывод

Отсутствие КМ подтверждено в текущих ответах, но утверждать, что поставщик вообще не может его предоставить, нельзя. Публичный API уже даёт больше справочных данных, чем использует приложение. Помимо КМ требуют уточнения расчётные часы, состав финансовых сумм, полнота списков и жизненный цикл заявки.

Подготовлен [запрос в поддержку](SUPPORT-REQUEST.md). Не отправлен. Приложение и рабочая база в ходе проверки не изменялись; выполнены только документированные чтения API. Новые исходные ответы со справочными персональными данными не сохранялись. [Доказательства](evidence.json) содержат схемы полей, количества и ID контрольных заказов, без ключей и значений персональных полей.

## Что проверено

- Официальная [документация API](https://tt-ok.ru/data/api_doc/), связанная с [описанием модуля](https://tt-net.ru/modules/api_integratsiya.html), справка и история изменений продукта. Опубликованы пять методов чтения; все пять проверены с действующим доступом. Методы создания/редактирования не вызывались. Недокументированные имена/параметры не перебирались.
- Все 2969 сохранённых исходных ответов GetOrders, независимо от нормализации приложения.
- Свежие GetOrders(OrderId=51025), GetOrders(OrderId=51824), GetOrders(FromOrderId=51820,ToOrderId=51830).
- Исходный Excel «Статистика 17.09.2026.xlsx», лист «ТрансТрейд», колонка M «КМ»: у 51025 значение 93, у 51824 — 0. Старые значения не доказывают неизменность текущей заявки.
- Действующий код загрузки, отчётов и импорта; требования из записи.

## Уже доступно: просить открыть заново не нужно

| Источник | Проверка | Что можем использовать сами |
|---|---|---|
| GetOrders | Сохранено 2969 ответов; свежие точечные чтения успешны | Суммы, даты, водитель, машина, клиент, исполнитель, менеджер, тип, адреса, заметки |
| GetClients | HTTP 200, error_code=0, 287 записей | ID и реквизиты клиентов, группы; синхронизация справочника ещё не реализована |
| GetCarriers | HTTP 200, error_code=0, 504 записи | ID исполнителя, группы, вложенные машины и водители; это не доказательство исторических смен |
| GetTransports | HTTP 200, error_code=0, 685 записей | ID, номер, марка, тип, грузоподъёмность, габариты; это вся доступная выдача, а не число собственных машин |
| GetDrivers | HTTP 200, error_code=0, 899 записей | ID и имя; это вся доступная выдача, а не число штатных сотрудников |

Четыре справочника пока не синхронизируются нашим коннектором. Это задача нашей разработки, а не блокировка провайдером. При подключении нужны контролируемое сопоставление существующих справочников, сохранение ручных правок и отказ от ненадёжного автоматического слияния имён. Для аналитики не нужны паспортные данные, которые API также возвращает.

В исходных заказах сохраняются поля дат/сроков оплаты, ClientPaidSum, параметры груза и контактов. Часть не выведена в интерфейс. Дополнительные отчёты по ним можно делать без запроса нового доступа; смысл начисления и фактической оплаты нужно разделять.

## Дополнительные наблюдения

- Все 2969 ответов содержат заполненные ClientSum/WorkerSum, начало и окончание; у 97 нет номера машины, у одной записи нет водителя. Причину пустых значений нельзя приписать API без сравнения с исходной карточкой. Среди записей есть начисления без поездки.
- Number пуст во всей выборке, ID присутствует. Просить «дать номер заявки» неверно: постоянный ID уже есть; произвольный номер — отдельное поле.
- Unload заполнен в 772 ответах, Cargo — в 53. Поля поддерживаются, но зачастую пусты. Сначала нужна сверка заполнения исходной системы, а не требование нового API.
- BonusSum и DispSum присутствуют, но во всей выборке равны нулю. Это не отсутствие поддержки полей.
- Status — настраиваемый словесный статус согласно [справке](https://tt-net.ru/help/status_zakaza.html). Наше распознавание отмены по текстовым префиксам не является универсальным контрактом отмены.
- [Архивные заказы](https://tt-net.ru/help/skrytie_zakaza_v_arkhiv.html) продолжают участвовать в отчётности самого продукта. Нельзя исключать их из аналитики только из-за архивирования.
- [Конструктор отчётов](https://tt-net.ru/help/konstruktor_otchetov.html) описывает более широкий набор полей, включая расходы и временные условия. Автоматическое серверное получение такого отчёта по опубликованному API не подтверждено; это альтернативный вопрос поддержке, а не готовое решение.
- [Порожний пробег](https://tt-net.ru/help/porozhnij_probeg.html) в отдельном отчёте продукта рассчитывается по дорожному пути между заявками. Это не спутниковое измерение. Для базовой интеграции приоритет — КМ заказа.

## Финансовые и временные оговорки из официальной справки

[Создание заказа](https://tt-net.ru/help/sozdanie_zakaza.html): продукт различает длительность, дополнительные часы и экспедирование; сумма исполнителю для привлечённой компании является платой подрядчику, а для своего водителя может иметь иной смысл. Поэтому ранее употреблённое общее слово «зарплата» для WorkerSum требует уточнения по правилам конкретной базы.

[Расходы по заказу](https://tt-net.ru/help/raskhody_po_zakazu.html): расходы клиента/исполнителя могут влиять на основные суммы согласно режимам учёта. При будущем подключении детализации нельзя автоматически вычитать её ещё раз из уже скорректированного итога.

## Что не следует включать в просьбу к ТрансТрейду

Фактический спутниковый пробег/моточасы/смены, операции Роснефти и Нефтьмагистрали, привязки топливных карт, развёртывание приложения и выдача логистам доступов относятся к другим источникам или нашей настройке. Планировщик и ручные причины простоев по исходному разговору ведутся отдельно. Не требуется закупка модулей или доступ на изменение заказов для данного исследования.

## Приоритеты

1. Получить КМ и объяснение пропусков списочной выдачи — блокируют достоверную основную сверку.
2. Уточнить расчётные часы, расходы и смысл финансовых сумм — предотвращают неверные показатели.
3. Получить контракт изменений/удалений и ID связей — для устойчивой автоматической синхронизации.
4. Самостоятельно добавить синхронизацию уже доступных справочников отдельной реализацией после контролируемого сопоставления.

Проверка не доказывает отсутствия частного расширенного API у поставщика, полноты всей его базы или доступности всех дополнительных модулей. Эти неизвестные сформулированы вопросами, а не утверждениями.
