# ТрансТрейд: проверка доступа 27.10.2026

Подключение API заблокировано отсутствием выданных API KEY и api_user_id. Рабочая синхронизация не реализована и не проверена; Excel остаётся текущим источником.

## Проверенные факты

- https://tt-ok.ru/data/api_doc/ требует API KEY и api_user_id; оба выдаются по электронной почте после подключения платного модуля.
- https://tt-net.ru/modules/api_integratsiya.html публикует цену 8800 ₽. Условия оплаты и наличие модуля у конкретной компании не подтверждены.
- В файле доступов на листе «Данные» A36 обозначает ТрансТрейд, A37/A38 — логин/пароль, значения находятся в B37/B38. Адрес базы и API-реквизиты в этом блоке отсутствуют. Секреты не печатались и не отправлялись.
- https://tt-ok.ru/ открыт в браузере: показана страница облачного хранилища, форма входа отсутствует. Это не кабинет конкретной компании.
- Поиск писем в подключённом Gmail по доменам transoft.ru, tt-net.ru, tt-ok.ru и названиям TransTrade/ТрансТрейд/api_user_id не дал результатов. Это не доказывает отсутствие письма в другой почте.
- Официальная инструкция мобильного приложения требует предварительных настроек базы, выданных при подключении; одного логина/пароля недостаточно: https://tt-net.ru/help/mobilnoe_prilozhenie.html .

## Точный следующий шаг

Владелец базы должен найти ранее выданные API KEY и api_user_id. Если модуль уже подключён, достаточно этих реквизитов. Если нет — сначала уточнить условия подключения у поставщика. Для проверки существующего кабинета потребуется адрес/настройки конкретной базы. Покупки и сообщения поставщику не выполнялись.

Текст запроса для владельца (не отправлен): «Подключён ли у нашей базы модуль API интеграция? Нужны выданные API KEY и api_user_id для чтения журнала заказов методом GetOrders. Если модуль не подключён, сообщите стоимость и условия; без отдельного согласования ничего не подключайте».

## Ограничения до реализации

GetOrders принимает FromOrderDate/ToOrderDate и диапазоны ID; явная пагинация, лимиты полноты, часовой пояс и удалённые записи в документации не определены. Реальный ответ необходим для проверки финансовых полей, отмен, пробега и соответствия Excel. Нельзя заменять Excel непроверенным ответом, складывать дубли или считать отсутствующие значения нулями. Сырые ответы должны сохраняться отдельно; частичная загрузка не должна удалять прежние заявки.
