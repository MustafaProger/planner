## Внешние ограничения и решения владельца

- В документированном `GetOrders` и реальных ответах нет километража. Для актуальной автоматической сверки км нужно, чтобы ТрансТрейд предоставил это поле/документированный способ чтения. Исторический пробег Excel виден в деталях; он не выдаётся за заново подтверждённый API-пробег.
- Часовой пояс базы ТТ в API не указан. Даты/время сохранены без сдвига, так же, как в Excel; нужен ответ владельца/провайдера о часовом поясе для сопоставления точных временных интервалов между системами.
- Счётчик общего количества, пагинация, tombstone удалённой заявки отсутствуют. Совпадение дневной и месячной выдачи — проверка согласованности, не доказательство полной базы. Отсутствие строки не означает отмену.
- Заявка 51824 (01.08.2026) найдена через `GetOrders(OrderId=51824)`, хотя дневной/месячный список и диапазон ID её пропускают. Обновлена существующая запись, Excel-снимок сохранён. Добавлена автоматическая проверка известных пропусков по ID; внутреннюю причину расхождения поставщик не сообщает. Подробности: [повторная загрузка](TRANSTRADE-RETRY.md).
- Сетевой блокер сентября снят: TLS зависал на маршруте VPN utun6, через en0 соединение работает. Только для ТТ настроена привязка сокета к en0, проверка TLS сохранена. За сентябрь получено 1088 заявок; повтор через UI не создал дублей.
- Привязки топливных карт к машинам отсутствуют в рабочей базе. Их вводит владелец по фактическим данным в готовой форме; назначать карты по имени держателя нельзя. Спутниковые показатели не распределяются по водителям без достоверных смен.
- Суммы Excel и текущего API расходятся для части заявок. Используются текущие значения API; прежний снимок сохранён. Причина разницы (редактирование либо особенности прежнего отчёта) не выдумывается. Для налоговой нормализации и «чистой прибыли» нужна утверждённая формула.
