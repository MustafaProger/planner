## Воспроизведение

Из корня проекта, Node.js 20 или новее:

```sh
npm ci
npm run browser:install
npm test
npm run test:browser
npm run test:browser:failure-probe
```

`npm run browser:install` соответствует `npx playwright install chromium`. Для Linux без системных библиотек браузера можно выполнить `npx playwright install --with-deps chromium` в своей тестовой среде. В production эти dev-зависимости и браузер не требуются. Соответствие версий обеспечивается lockfile и установкой браузера CLI именно из checkout; это предусмотрено [документацией Playwright](https://playwright.dev/docs/browsers).

Используется Playwright Test с управляемыми fixtures, а не прежний `node --test tests/test_sidebar_scroll.cjs`; выбор runner соответствует [официальному описанию Library/Test](https://playwright.dev/docs/library). Опциональный `PLAYWRIGHT_CHANNEL=chrome` разрешает явно выбранный системный браузер, но обычная команда и приемка от него не зависят.

Дополнительно выполнен запуск из `/tmp` через абсолютные пути к CLI и конфигурации временного checkout: **2 passed за 1,669 с** вместе с запуском runner. Статика разрешается от файла теста, не от текущей папки. Среда приемки: Node v24.15.0, npm 11.12.1, Playwright 1.64.1, Chromium 156.0.8078.4, macOS arm64.

## Ошибки и завершение процессов

Команда `test:browser:failure-probe` последовательно вводит два сбоя только в синтетический тест:

| Сбой | Ожидаемый результат | Фактическое время | Cleanup |
|---|---|---|---|
| Несуществующий selector `missing-probe` | Timeout локатора 3000 мс, runner exit 1 | 3,587 с | Собственный браузер завершен, аварийная остановка не потребовалась |
| Искусственный сброс sidebar scroll в 0 | Assertion `sidebar scroll after navigation`, runner exit 1 | 0,644 с | Собственный браузер завершен, аварийная остановка не потребовалась |

Негативный launcher имеет независимый предел 20 с для каждого дочернего runner, фиксирует PID только своих запущенных браузеров и проверяет их завершение. При срабатывании предела он останавливает только свои процессы/группы и возвращает ошибку, а не объявляет cleanup успешным. Диагностические логи пишутся в игнорируемый `.local/`.

Причина прежней внешней длительности 563,7 с не установлена; этот результат не объясняется задним числом. Новое доказательство относится к нынешнему runner, явным пределам и измеренным сценариям успеха/ошибки.

Все browser contexts временные; рабочие профили, авторизация, БД, scheduler и поставщики не используются. HTTP-трафик приложения полностью перехвачен на `http://fleet.test`. Приемка данного файла не выполняет deployment и не запускает локальный рабочий сервер.
