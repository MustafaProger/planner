## Оставшиеся границы полноты

1. **Актуальный пробег ТТ.** API не отдаёт поле км. Историческое значение Excel доступно как прежний источник, но не считается заново подтверждённым. Для полноценной автоматической сверки нужен поддерживаемый источник текущего километража.
2. **Полнота/удаления ТТ.** Дневная и месячная выдачи сверяются, известные пропуски проверяются по ID; это не доказывает полную базу поставщика. Нет документированного общего счётчика и признака удаления. Пропавшая строка сохраняется для проверки.
3. **Время.** Часовой пояс базы ТТ не указан в ответе. Календарные даты сохраняются без сдвига. Сравнение точных межсистемных интервалов требует подтверждённой договорённости о часовом поясе.
4. **Топливо и экономика.** Карты ещё не сопоставлены с автомобилями, ручные расходы не заведены. Покупка по карте не равна расходу топлива двигателя; автоматического распределения по отдельным рейсам/водителям нет.
5. **Power Pivot и налоги.** Сохранена бизнес-логика подтверждаемых показателей, а не все DAX-меры. Лист Рент не задаёт однозначной формулы пересчёта; «чистая прибыль» без утверждённого состава затрат не выводится.
6. **Исходные исключения.** Служебные ресурсы, неназначенные планы и возможные дубли требуют решения владельца. Аудит не создаёт вымышленные назначения или привязки ради заполненного отчёта.

Для пользователя подготовлено [Руководство заказчика](../Руководство-заказчика.md). Календарь планирования дополнен переключением строк «Маршруты / Автомобили» для обеих исходных сводных. Три Node-проверки `tests/test_planviews.cjs` проходят: группировки сохраняют каждое назначение и его стабильные действия ровно один раз, пользовательский текст экранируется, выбор сохраняется при повторном отображении и переключении списка/календаря, пустые/неназначенные строки объясняются. Проверки внешнего вида и обновления выполняются отдельно главным агентом; этот документ подтверждает состав и трактовку данных, а не заменяет браузерные проверки.
