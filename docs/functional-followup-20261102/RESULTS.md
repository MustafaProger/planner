## Основание и конкретный пробел

Требования заказчика R09/R19/R20/A9 предусматривают раскрытие отклонения до даты, заявок и источника спутниковых показаний; согласованность плановых итогов с деталями; отдельное сравнение будущего плана и фактических заявок за одну сущность и период; общую выборку таблицы, деталей и экспорта. В исходной беседе, 19:13–20:06, заказчик рассматривает подозрительные часы/километры и возможную ошибку даты или количества заявок; в 27:25–28:22 — сопоставление месячного плана с фактом.

До этой доработки `workspaceReport` выводил строки «Сводки плана» и «План–факта» без раскрытия. В сверке нажатие строки показывало только заявки ТТ, хотя исследовать требовалось обе стороны. Переход к нужному дню календаря требовал повторного выбора контекста. Предыдущая приемка подтверждала расчеты и наличие отчетов, но не закрывала весь этот пользовательский путь.

Кнопка календаря и карточки деталей — способ реализовать данный сценарий. Требование не превращается в автоматическое построчное сопоставление маршрутов, новую налоговую модель или распределение частичного дня.

## Что изменилось

| Было | Реализовано | Как пользоваться |
|---|---|---|
| Плановые итоги нельзя было раскрыть из строки отчета | Детализация «Сводки плана» показывает показатель строки, учтенные назначения и записи вне итога с причиной. Период, машина, водитель и выбранная группировка совпадают со сводкой | Нажать строку или выбрать ее клавиатурой и нажать Enter |
| В «План–факте» были суммы и дельты без состава обеих сторон | В одной карточке отдельно показаны назначения и фактические заявки-рейсы. Доплаты/удержания видны отдельно и не увеличивают показатели рейсов. Полнота вычисляется по исходному периоду отчета, а не только по выбранной группе | Открыть нужную машину, водителя или пару; сверить показатель с исходными строками |
| Сверка и предупреждение в обзоре раскрывали только заявки | Общая карточка машино-дня показывает заявки, эффективные спутниковые показатели с источником каждого показателя, затем исходные интервалы Excel. Замена отдельного показателя API и сохраненный показатель Excel объяснены явно | Открыть строку «Сверки со спутником» или отклонение в «Обзоре сверки» |
| День календаря приходилось выбирать повторно | «Открыть день в календаре» переносит машину/месяц/день и выделяет день. Back/Forward восстанавливают контекст отчета/календаря | Перейти из карточки, проверить день, вернуться кнопкой браузера |

Детали берутся читающими API из той же логики отбора и группировки, что сводка; название пары не разбирается по разделителю. Совпадение агрегатной группы не объявляется соответствием отдельных плановых и фактических рейсов. Неизвестный показатель и неподтвержденная дельта сохраняют состояние «—». Для дня только со спутниковыми данными календарь показывает выбранный контекст и отсутствие фактических записей, не создает заказ или простой.

## Проверка через настоящий интерфейс

[Браузерный сценарий](browser.cjs) и [его временный сервер](server.py) воспроизводят работу с настоящими Flask API и SQLite на полностью синтетических данных. До импорта сервера задаются отдельный временный `FLEET_DATA` и `FLEET_SCHEDULER=disabled`; используются свой случайный порт, тестовые admin/viewer и сохраненный fake-ответ спутника. Реальные базы, учетные записи и поставщики не задействованы; изменяющие endpoints поставщиков запрещены, все внешние браузерные запросы блокируются. Сервер и browser закрываются, временная база удаляется.

Отдельная регрессия воспроизводит позднее завершение отчета при уже открытых деталях: редактирование сохраняет показанную версию записи, а не берет новую версию из общего кеша. Итоги общих Python/JS/sidebar-прогонов фиксируются в [едином текущем итоге](../current-status.md), отдельно от четырех живых сценариев выше.

После установки Python-зависимостей в `.venv`:

```sh
npm ci
npm run browser:install
node docs/functional-followup-20261102/browser.cjs
```

`ACCEPTANCE_PYTHON` задает иной Python, `ACCEPTANCE_OUTPUT` — каталог результата. По умолчанию повторный запуск пишет JSON/скриншоты в `.local/functional-followup-20261102/`, сохраняя этот датированный отчет. Установлены 7-секундные ожидания UI и общий предел 120 с; завершаются только собственные процессы.

Проверка относится к локальной реализации, а не к ее публикации. Автоматическое получение КМ ТТ остается отложенным. Точный маршрутный матч, налоговые коэффициенты и правила долей дня в эту доработку не добавлялись; показанные карточки объясняют существующие расчеты.
