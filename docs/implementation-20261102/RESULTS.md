## Что изменено

- G01: пути исходных книг настраиваются через параметры, окружение или приватный JSON; относительные пути внутри JSON отсчитываются от файла настройки. Заполненная база не требует книг при старте. API-тесты используют собственные маленькие XLSX, а семь проверок реальных книг выделены отдельно. Ненужный повреждённый config не блокирует приоритетные параметры окружения.
- G02: подтверждение полноты относится к проверенному содержимому периода. Preview показывает состав/суммы и отпечаток; изменение данных до сохранения даёт 409. После содержательной правки подтверждение устаревает; повтор без изменений его сохраняет.
- G03–G05: добавлены разрезы текущей марки/принадлежности/ресурса, разные средние по записям и рейсам, все шесть отклонений план–факт со знаком факт минус план и причинами недоступности. Фильтры, детали и CSV используют одну выборку; историческая принадлежность не выдумывается.
- G06: удаление проверяет показанную пользователю версию; связанная группа статусов защищена отдельным токеном состава. Изменившаяся запись даёт 409 и явное перечитывание. Используются транзакция, проверки роли и soft-delete.
- G07: новый раздел «Контроль → Километраж и смены» принимает CSV/XLSX через проверку и подтверждение; хранит источник, время, хеш файла и историю. Проверяются ID/номер/дата/машина, конфликты, пустое значение и ноль, поздние исправления. Изменение идентичности заявки делает дополнение устаревшим. Это ручной импорт проверенного отчёта, а не заявленная готовность автоматической выгрузки из ТТ.
- G08: реальные интервалы водитель–машина с часовым поясом, историей и проверкой пересечений. 27 часов не обрезаются. Суточное измерение относится водителю только при единственной смене, покрывающей сутки целиком; остаток сохраняется на машине, пропорциональное распределение не применяется.
- G09–G12: конкретная приватная очередь качества; безопасные коды сетевых ошибок; проверены существующие механизмы catchup, backup/restore, Linux preflight и уведомлений с тестовым транспортом. Реальные назначения, расходы и каналы не подменялись тестовыми.
- При живой проверке дополнительно исправлены прямой адрес нового раздела (404 при перезагрузке), скрытые фильтры его периода и запоздалые ответы preview/confirm при повторном открытии формы.

Первая проверка метаданных остановилась на неверном имени столбца до любых изменений; имя проверено по схеме, затем применена аддитивная миграция.

## Что требуется для завершения

1. **КМ:** свежий отчёт ТТ по 3–5 заявкам и поддерживаемый способ автоматического получения сохранённого поля. Готов [точный запрос владельцу ТТ и схема VPS](TT-MILEAGE-NEXT-STEP.md); запрос не отправлен. Текущий ручной импорт уже проверен, реальных КМ пока нет.
2. **Факты:** подтверждённые интервалы водитель/машина/начало/конец, история 25 карт, решения по 91 проблемному назначению, подтверждённые расходы/простои/полнота. Детали приватной очереди доступны в отчёте данных. Догадочные назначения не внесены.
3. **VPS:** известны намерение и наличие сервера, но не получены конкретный адрес/ОС/домен/способ подключения. После назначения хоста нужны перенос актуальной базы и приватной конфигурации, Linux-сеть вместо локального `en0`, web+worker, HTTPS, backup/restore и проверка после перезагрузки. Реальная установка ещё не проводилась.
4. **Уведомления:** конкретный канал и получатель, затем настройка и проверка реальной доставки. Пока проверен только тестовый транспорт.

Публикация на VPS даст постоянное место исполнения, но сама по себе не добавит КМ в API ТТ. Предпочтителен API с этим полем; резерв — подтверждённый экспортер отчёта и доставка файла на VPS. Нужность отдельного Windows-места определяется способом выгрузки, не фактом существования Linux-планировщика.

Git index не изменялся, новый commit SHA отсутствует. Дополнительно последний `git fetch origin` получил reset соединения SSH к GitHub; свежая удалённая история не подтверждена. Перед будущим push требуется повторная сверка remote и сохранение всех текущих зависимостей без force.
