Рост количества топливных операций относительно исследовательского снимка допустим при работающем worker; это отдельное фоновое обновление, а не ручной расход.

Существующие формы уже позволяют завершить разбор. Нужны конкретные входы:

- Для 88 назначений — водитель/автомобиль на указанную дату по журналу; для двух дублей — отдельная смена либо отмена конкретной записи; для ручного review — основание назначения.
- Для каждой из 25 карт — провайдер, номер карты, автомобиль, начало/конец использования и источник подтверждения. Держатель/комментарий карты не доказывает историческое назначение. Очередь содержит диапазон и количество затрагиваемых операций.
- Для дополнительных расходов — дата, машина, категория, сумма, документ. Покупки топлива повторно не вводятся. Отсутствие расходов не подтверждает нулевые затраты.
- Для полноты — проверенный руководителем весь парк и период каждого источника; актуальная версия показывается до подтверждения. Причины простоев после августа берутся из журнала, а не из пустых дат.

## Развертывание и резервное восстановление

Действуют существующие `deploy/*` и `docs/server-autonomy-20261030/DEPLOYMENT.md`. В проекте найден шаблон `fleet.example.invalid`, а не назначенный сервер/домен. Отдельные web/worker и observer, systemd restart/watchdog, preflight и backup уже существуют; новая система не создавалась.

Свежий preflight текущего Mac прошел. Проверка той же конфигурации как Linux ожидаемо отклонила специфический маршрут macOS; он не исправлялся и не копировался на другой хост. Это конкретная зависимость переноса, а не общая ошибка API.

Скрипт `deploy/backup.py` создал согласованную свежую SQLite-копию. Новая схема применена только на копии. Все защищенные исходные таблицы совпали до/после. Затем из копии восстановлена вторая изолированная SQLite: integrity_check=ok, **все 16 таблиц совпали построчно**. Секреты и JSON-истории в эту SQLite-проверку не входят; для серверного переноса нужен согласованный полный снимок постоянного каталога. Старую БД поверх текущей не восстанавливали.

Нужные параметры активации: конкретный Linux/systemd хост и владелец доступа; домен и TLS; постоянный каталог/служебный пользователь; период исторического охвата; проверенный с этого хоста сетевой доступ к каждому поставщику; согласованный перенос свежей БД и JSON-историй. Сама установка, reboot, systemd и HTTPS на целевом сервере здесь **не проверены** — целевой хост не назначен.
