# Отчёты, полнота и конкурентные действия — реализация 2 ноября 2026

Этот документ фиксирует изменения агента reporting. Рабочие бизнес-данные не изменялись. Исходная резервная копия главного агента: `.local/implementation-20261102T075526Z`.

## G03 — марка и принадлежность

`analytics.report` подготавливает по одной строке на исходную запись, добавляя `vehicle_brand`, `vehicle_company`, `driver_company`, `resource_type`. Ссылки на справочники разрешаются по стабильному ID, включая объединённые записи; текстовое совпадение допускается только при отсутствии ID и единственном соответствии. Неизвестное не выводится из исполнителя, ФИО или номера машины: остаётся «Не указано».

Все четыре ключа доступны как группировки и фильтры статистики. API возвращает подготовленные исходные строки, из которых строятся сводка, графики, детали и CSV. В интерфейсе и экспорте явно обозначен текущий справочник: датированной истории принадлежности эти изменения не создают. Неподдерживаемая группировка возвращает ошибку валидации. Фильтр компании водителя блокирует приписывание ему полной спутниковой телеметрии машины так же, как фильтр конкретного водителя.

## G04 — все отклонения план–факт

Один API результат содержит шесть пар и дельт. UI предлагает «Деньги» (выручка/выплаты), «Работа» (рейсы/дни), «Пробег и время» (км/часы заявок). Для каждой метрики показаны план, факт, знак `факт − план`; ноль отличается от отсутствующего значения. Причина отсутствующей дельты возвращается в `delta_reasons`, рядом с «—». Известный факт продолжает отображаться при неподтверждённой полноте или отсутствующем пробеге. Выбор показателей хранится в состоянии навигации и не сбрасывается при обновлении. CSV содержит все API поля, включая причины.

## G05 — однозначные средние

Выбор «Средние показатели» в статистике показывает:

- сумму и выплату всех неотменённых записей / число этих записей;
- выручку и выплату только рейсов / число рейсов;
- пробег ТТ и длительность заявок-рейсов / число рейсов;
- всю выручку, включая начисления и удержания, / число рейсов как отдельный показатель.

Формулы доступны под таблицей и в CSV средних. Итог всей выборки вычисляется из исходных записей, а не усреднением групп. При неизвестном числителе основная метрика остаётся неизвестной; нулевой знаменатель даёт `null`. Суммы/количества известных значений остаются в API (`known_sums`, `average_counts`, `missing`, `trip_missing`).

## UI G02/G06 и G07/G08

Coverage preview показывает весь выбранный период и все машины: число исходных, исключённых и требующих проверки записей, рейсы, суммы, пробег и часы. Подтверждение отправляет отпечаток именно полученного preview и его алгоритм; изменение границ сбрасывает preview и checkbox. Список показывает устаревшие подтверждения отдельно. Backend проверки разработаны агентом integrity.

Удаление статуса, назначения, ручной заявки и дополнительной записи передаёт версию, увиденную при открытии формы/экрана; статусы передают также токен состава связанной группы. При 409 нет автоматической повторной операции: пользователь получает явное «Перечитать данные». Импортированные заявки по-прежнему не получают кнопку удаления.

Добавлен пункт «Километраж и смены» (`/control/evidence`) и подключение отдельного `evidence.js`, разработанного агентом evidence. Детали заявки показывают источник, время актуальности, версию и состояние дополнения километража.

G09: состояние назначения `review`, даже без флага дубля, теперь появляется отдельным действием «Спорное назначение» на странице качества; `no_route` сохранён как сознательное исключение.
