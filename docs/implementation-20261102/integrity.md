# G02 и G06 — подтверждение данных и конкурентное удаление

Проверено 2 ноября 2026 на изолированных SQLite и временных HTTP test clients. Рабочие записи этим этапом не изменялись.

Подтверждение полноты хранит отпечаток бизнес-полей за выбранные источник и даты, алгоритм, автора и время проверки. Предварительный просмотр возвращает количество записей/исключений/неразобранных случаев, исходные суммы и отсутствующие показатели для всего парка. Сохранение под SQLite write-lock повторно проверяет именно просмотренный отпечаток. Новая/измененная/удаленная строка, перенос даты, изменение категории, merge сущностей и эффективного километража делают проверку устаревшей. Заметка и неизменившийся API/Excel-повтор ее не сбрасывают. Исходное подтверждение остается в записи; оно не переписывается на новую версию автоматически. Историческая запись без отпечатка требует повторного подтверждения.

Удаление проверяет переданную версию, права и разрешенность операции до мутаций. SQL использует `id/revision/deleted=0`; один SQLite write-lock защищает группу связанных статусов от межпроцессного изменения. Статусы получают токен полного состава ID и версий. Если состав или любая версия изменились, возвращается 409 и ничего не удаляется. Импортированные заявки удалять нельзя. Карты, расходы и подтверждения полноты тоже удаляются логически с проверкой revision; для старой coverage добавляется столбец deleted без изменения содержимого.

Затронуты `app/coverage.py`, `workspace.py`, узкие hooks в `server.py`, `reports.coverage` и удален безусловный сброс в `transtrade.apply`. UI исполняет тот же контракт: просмотренная версия, явное перечитывание при 409, никакого автоматического удаления с подставленной свежей версией. UI и живой браузер проверяются отдельным отчетом.

Проверки:

- `tests/test_integrity_gaps.py`: 18 сценариев — legacy, stale preview, create/edit/delete, перенос между периодами, no-op импорт/ТТ, деньги/отмена/категория, пустой полный период, merge, статусы и дополнительные таблицы, две реальные SQLite connections одновременно, занятый writer без частичного удаления, HTTP 409/403/CSRF.
- Совместный запуск `test_integrity_gaps.py test_workspace.py test_transtrade.py test_transtrade_reconciliation.py`: **82 passed**.
- Тесты прежнего контракта обновлены на явный preview; они не обходят новый контроль подстановкой текущей версии внутри DELETE.
- Копия свежей рабочей БД прошла additive schema migration; содержимое snapshot/users/manual/audit/records/catalog/tariffs/transtrade_orders/transtrade_history побайтно по строкам не изменилось. Restore проверен отдельно в `data-and-deployment.md`.

Ограничения: механизм не подтверждает реальные периоды за пользователя. В рабочем снимке coverage=0. Изменение отчетной семантики в будущем должно сопровождаться изменением версии алгоритма отпечатка и повторной проверкой периодов.
