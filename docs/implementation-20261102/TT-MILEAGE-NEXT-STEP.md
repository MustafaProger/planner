# Как подключить КМ ТТ при размещении планировщика на VPS

2 ноября 2026. Технический запрос подготовлен, **никому не отправлен**. Никакие модули, лицензии или серверы не приобретались.

Проблема решаема. Отсутствие установленного клиента на вашем компьютере не мешает существующему API получать заявки и деньги: этот путь уже работает. Однако в свежем `GetOrders(OrderId=51824)` 2 ноября в 11:03:55 МСК поля сохраненного километража нет. VPS сам по себе не добавит поле в ответ поставщика.

## Что можно сделать сейчас

1. Получить из действующей базы один свежий отчет либо печатное подтверждение КМ для 3–5 контрольных заявок. Это может сделать сотрудник, у которого уже открыт ТТ. Достаточны внутренний API ID (если доступен), отображаемый номер, дата, машина, сохраненные КМ и время формирования. Не требуется повторно вводить заявки в планировщик.
2. На этом примере проверить новый адаптер «Контроль → Километраж и смены»: preview, сопоставление, подтверждение, позднее исправление и повтор без дублей. Это докажет корректность значения, но ручная выгрузка останется временным способом.
3. Для постоянной работы на VPS сначала установить поддерживаемый серверный способ чтения КМ: поле в API, отдельный read-only endpoint либо регулярный файл, который формирует сам ТТ. Ниже готов узкий запрос.
4. Только если провайдер подтвердит, что выгрузка требует Windows-клиента, выбирать постоянно работающее Windows-место и способ его запуска. До этого нет доказанной необходимости покупать Windows VPS или переносить сам ТТ на сервер планировщика.

## Что официально известно о рабочем месте

- Для desktop-клиента производитель указывает Windows, а для формирования/просмотра документов и отчетов — Word/Excel. Это описание клиентской программы, не ограничение ОС нашего планировщика. [FAQ TransTrade](https://tt-net.ru/faq/).
- Если подключен модуль «Интернет-сервер», корпоративный комплект клиента можно получить по ранее выданной ссылке либо скопировать с рабочего места коллеги; он включает `TransTrade.exe`, `config.set`, бланки и служебные файлы. Демо-версия сама по себе не подключит существующую базу. Не нужно публиковать `config.set` или пароли в Git/чате. [Установка на новом рабочем месте](https://tt-net.ru/help/ustanovka_programmy_na_novom_rabochem_meste.html).
- «Интернет-сервер» описан как облачное хранение данных при прежнем интерфейсе программы. Это не обещание веб-экспорта или server-side CLI. [Описание модуля](https://tt-net.ru/modules/internet_server.html).
- В официальной истории от 16.09.2026 упомянута веб-версия TransTrade.ONLINE с модулями «Интернет-сервер» и «Мобильные приложения». Из этого не следует, что она подключена у нашей базы или позволяет выгружать КМ автоматически. [История изменений](https://tt-net.ru/innovations/).
- Сохраненное поле километража предусмотрено как `$КМ$` в печатной заявке; конструктор отчетов поддерживает выбор столбцов и Excel-бланк. Доступность нужного поля и API ID в установленной версии нужно проверить. [Переменные заявки](https://tt-net.ru/help/peremennye_dlya_blanka_zayavki.html), [конструктор](https://tt-net.ru/help/konstruktor_otchetov.html).

## Текст технического запроса владельцу/разработчику интеграции

> Используем действующий модуль API TransTrade для чтения заявок. Планировщик будет работать самостоятельно на Linux VPS. Нужен только read-only доступ к **сохраненному в заказе полю КМ, которое заполняет логист**, а не расчетному расстоянию маршрута и не спутниковому пробегу.
>
> 02.11.2026 в 11:03 МСК запрос `GetOrders` с `OrderId=51824` успешно вернул запись, но в ответе нет поля КМ. В официальной справке сохраненное поле доступно в печатной форме как `$КМ$`.
>
> 1. Можно ли включить это поле в `GetOrders` для нашей базы либо предоставить поддерживаемый read-only метод? Нужны точное имя поля, единицы, различие пустого значения и нуля, версия API и пример ответа с API ID/КМ. Расширенные денежные поля не требуются.
> 2. Как получить позднее исправление КМ: есть ли время изменения с часовым поясом или рекомендуемый период повторного чтения? Внутренний API ID должен оставаться постоянным; отображаемый номер не используем как единственный ключ.
> 3. Если API этого не поддерживает, какой штатный отчет выводит КМ вместе с API ID (либо номером, датой и машиной)? Просим пример свежей выгрузки 3–5 заявок с нулевым и ненулевым значением и временем формирования.
> 4. Может ли этот отчет формироваться **без открытого браузера и ручных действий**, по расписанию/CLI/документированному endpoint? Если да, нужны точная команда или контракт, поддерживаемая ОС/версия, требование запущенной пользовательской сессии и способ доставки файла. Наличие ручной кнопки «Экспорт» этого не подтверждает.
> 5. Если обязательна клиентская программа: какой корпоративный комплект и конфигурация нужны для входа в нашу существующую базу; можно ли использовать уже лицензированное рабочее место? Новую лицензию, модуль или изменение прав просим сначала явно назвать и обосновать, не подключать автоматически.
>
> Обратная запись/создание/редактирование заказов не нужны. Предлагаем проверить один текущий заказ, затем изменение его КМ и два повторных чтения; деньги, ID и число заявок не должны меняться.

## Возможная схема VPS — после подтверждения источника

**Предпочтительный вариант:** Linux VPS запускает web+worker планировщика; worker читает действующий API ТТ с добавленным КМ. Дополнительный desktop-клиент для регулярной загрузки не нужен. Это проектный вариант, включение поля поставщиком пока не подтверждено.

**Резервный вариант:** поддерживаемое рабочее место/экспортер ТТ формирует файл с КМ и временем источника; защищенный канал доставляет его на Linux VPS; планировщик проверяет целостность, ID и актуальность. Сейчас реализован ручной preview/confirm. Автоматическое доверенное принятие файлов потребует отдельной настройки конкретного подтвержденного источника и транспорта; оно не включено под видом готовой автономности.

Автоматизация Windows UI — крайний вариант после испытания конкретного доступного рабочего места. Нельзя обещать надежный серверный режим по факту существования кнопки в программе. Размещение Linux-планировщика можно готовить независимо от выбора этого пути; доступные деньги и длительности заявок продолжат обновляться.
