# Километраж TransTrade — анализ 5 ноября 2026

Пользователь подтвердил: КМ заполняются в самой программе TransTrade, но отсутствуют в имеющемся API. Требуется получать именно сохранённые значения. Спутниковый пробег, норматив маршрута и старые Excel не заменяют эти данные.

## Свежая проверка сервера

- Рабочая версия: `/opt/fleet-analytics/releases/20261102-3b04add`.
- `fleet-web.service` и `fleet-worker.service` активны; `/healthz` возвращает `ok`; SQLite `integrity_check=ok`.
- В момент снимка: 18 619 заказов TransTrade, 0 строк `mileage_observations`.
- Прямое чтение `GetOrders(OrderId=51824)` 5 ноября в 16:20 МСК вернуло одну заявку; среди ключей ответа нет КМ/пробега/distance/mileage.
- API-загрузки TransTrade, Нефтьмагистрали и Роснефти успешны. У мониторинга уже имеется отдельная ошибка; последнее успешное обновление — 4 ноября, 10:29 МСК. Причина в рамках этой задачи не исследовалась.
- Рабочие данные, конфигурация, доступы и опубликованный код не изменялись; дополнительный worker не запускался.

## Выбранный следующий шаг

Первым проверить TransTrade.ONLINE как потенциальный источник, доступный с Linux VPS без Windows-клиента. Наличие сохранённого КМ в ответах веб-версии пока **не подтверждено**. Не реализовывать интеграцию по предположению о названии поля.

Для входа нужны логин, пароль, номер и код организации. Логин и пароль имеются в существующем закрытом файле доступов; номер и код отсутствуют. Пользователь сообщил, что попробует получить их. Реквизиты следует сохранить в этом закрытом файле, не в Git или отчёте.

Существующий механизм `app/mileage.py` уже поддерживает подтверждённый импорт отчёта с КМ, историю значений и проверку соответствия заявки. Он не является автоматическим чтением из TransTrade.

## Передача по цепочке субагентов

1. **Анализ:** выбран кандидат TransTrade.ONLINE; обязательный следующий шаг — проверить реальный источник после получения доступа. Резервный путь — подтверждённый экспорт из корпоративного Windows-клиента. Автоматическое формирование такого экспорта пока не установлено.
2. **Реализация:** сначала прочитать несколько известных заявок, найти документированное либо фактически проверенное поле сохранённых КМ и сравнить его с программой. Затем добавить отдельный адаптер к существующему механизму наблюдений, устойчивый к повторным загрузкам, поздним исправлениям и изменению идентичности заявки. Не записывать в TransTrade. Перед публикацией проверить локально на изолированных данных и сделать серверную резервную копию. Этот этап ещё не выполнен.
3. **Независимая проверка:** сравнить КМ реальных заявок с первоисточником; проверить пустое значение и настоящий ноль, повтор без дублей, позднюю корректировку, сохранение после обычного API-sync, отчёты и сверку со спутником, права и восстановление фонового процесса. Зафиксировать неизменность денег, заказов и доступов. Этот этап ещё не выполнен.

Реализация на рабочем сервере разрешена текущим поручением пользователя. Сейчас её ограничивает отсутствие доступного проверенного источника КМ, а не отсутствие разрешения на выпуск.

## Дополнительная проверка: экспорт отчёта по расписанию

По последующему поручению пользователя 5 ноября проверены официальная справка и история изменений. **Штатное автоматическое формирование отчёта с сохранёнными КМ в CSV/Excel по расписанию не подтверждено.** Это граница найденной документации, а не доказательство отсутствия недокументированной или заказной функции. Установленная корпоративная Windows-программа недоступна для практической проверки.

Подтверждённые сведения:

- [Конструктор отчётов](https://tt-net.ru/help/konstruktor_otchetov.html) описывает выбор заявок, шаблона и ручное нажатие «Сформировать». В шаблон добавляются поля заказа; отдельно предусмотрен бланк Excel. Команда фонового запуска и расписание здесь не описаны.
- [Резервное копирование](https://tt-net.ru/help/rezervnoe_kopirovanie.html) имеет расписание, но создаёт копии базы. Для локальной базы проверка срока копирования выполняется при завершении сеанса. Это не регулярная выгрузка выбранных полей в отчёт.
- [Рассылка писем](https://tt-net.ru/help/rassylka_pisem.html) содержит автоматические уведомления по событиям; расписание формирования нужного табличного отчёта не описано.
- [Сервисная утилита](https://tt-net.ru/help/servisnaya_utilita.html) описывает настройку подключения и обслуживание клиента; документированный экспортёр отчётов/CLI не найден.
- [Офис-обмен](https://tt-net.ru/help/ofis_obmen.html) описывает перенос новых записей с помощью резервной копии; изменения существующих заказов не переносятся. Для поздних исправлений КМ этот механизм не подходит без дополнительных возможностей.
- В изученных разделах [запуска](https://tt-net.ru/help/zapusk_programmy.html), [параметров системы](https://tt-net.ru/help/parametry_sistemy.html), [дополнительных настроек](https://tt-net.ru/help/dopolnitelnye_nastrojki.html) и [истории изменений](https://tt-net.ru/innovations/) команда либо настройка расписания такого экспорта также не найдена.

Техническое ограничение нашего текущего импортёра: `app/mileage.py` принимает XLSX или CSV UTF-8 с заголовками `provider_id` либо `number`, а также `date`, `vehicle`, `km`. Старый XLS напрямую не поддерживается. Документация TransTrade допускает XLS-бланк; реальный формат сформированного файла ещё нужно проверить. Для автоматического приёма потребуется отдельный доверенный адаптер вместо ручного preview/confirm.
