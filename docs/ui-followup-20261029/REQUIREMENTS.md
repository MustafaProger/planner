## Связи схем Power Pivot и их эквивалент

| Связь на изображениях | Как работает приложение |
|---|---|
| Календарь → Логист / ТрансТрейд / Спутник / Статус | Дата каждой фактической записи; календарные группы вычисляются (`analytics.report`, `reports.plan_rows`). Отдельные 365/730 строк календаря не становятся деловыми операциями. |
| Логист → УТ_Водители | `plans.driver_id` → справочник водителей; компания и признак партнёра. Сумма выплаты сохраняется при назначении. |
| Логист → УТ_Автомобили | `plans.vehicle_id` → автомобиль/ресурс; марка и принадлежность разделены. Служебная строка не маскируется под госномер. |
| Логист → маршрут и ставки | `route_id` → `tariffs` по дате; в плане сохранены выручка/выплата/км/часы и ссылка на тариф. |
| ТрансТрейд → СП1 Клиент | `client_id` → `clients`; группировка по клиенту. |
| ТрансТрейд → СП2 Исполнитель | `carrier_id` → `carriers`; группировка по исполнителю. |
| ТрансТрейд → СП3 Водитель | `driver_id` → `drivers`; отдельная статистика водителя и пары. |
| ТрансТрейд → СП4 Тип транспорта | `type_id` → `transport_types`; тип не заменяет классификацию рейса/штрафа. |
| ТрансТрейд → СП5 Номер автомобиля | `vehicle_id` → `vehicles`; вариант написания можно связать с основной записью, исторические ссылки сохраняются. |
| ТрансТрейд → СП6 Расчёт клиента / СП7 Расчёт исполнителя | `payment_id` / `payout_method_id` → общий каталог `payment_methods`, но разные поля записи и разные группировки. |
| Спутник → автомобиль + дата | Excel использует таблицу соответствий объекта; API — уникальный полный госномер. Сведение по машине/дню, показатели API заменяют одноимённые Excel-показатели, не складываются повторно. |
| Статус → автомобиль или водитель + дата | `statuses.kind`, `entity_id`, дата и причина. Отдельные факты простоя, не деньги и не заявки. |
| Дополнительная связь топлива → автомобиль | Карта + провайдер + даты → `card_bindings.vehicle_id`. Это новая необходимая бизнес-связь, в исходных схемах её нет и она сейчас не заполнена. |

Все отображённые связи предметной области представлены. **Буквальное равенство всех DAX-мер и фильтрующих контекстов Power Pivot не доказано:** встроенные модели бинарные и не исполнялись в этом аудите. Проверены видимые таблицы/поля/сводные, контрольные агрегаты и исходный код соответствующих расчётов. Например, «Выплаты / выручка, %» есть, но это не доказательство совпадения любого произвольного DAX-выражения `% от выручки` на скриншоте.

## Что требуется для завершения незакрытых сценариев

1. **Актуальный заявленный километраж:** установить документированный источник поля ТТ либо отдельный подтверждаемый показатель задания. Норматив маршрута и спутниковый пробег нельзя выдавать за километраж из ТТ без явно согласованного изменения смысла сверки.
2. **Фактическое время и водитель:** определить, что сравнивать — интервал выезда/возврата, движение, работу двигателя или смену; получить соответствующие интервалы и достоверные назначения водителей. Текущее суточное API этих границ не хранит.
3. **Историческое покрытие:** догрузить необходимые периоды спутника, затем проверить полноту по машинам/дням. Сентябрь сейчас отсутствует; автообновление предыдущих суток не закрывает этот пробел. Запуск загрузки в рамках настоящего аудита не выполнялся.
4. **Топливо и экономика:** заполнить реальные привязки карт по датам и недостающие расходы. Утвердить, нужен денежный остаток после покупок или себестоимость израсходованного топлива, и формулу налогов/прочих затрат. Затем реализовать показатель прибыли на сопоставимый километраж из исходного задания.
5. **План–факт:** разобрать спорные/неназначенные планы и подтвердить реальные полные периоды. Не подтверждать их автоматически только потому, что запрос API вернул успех.

Эти пункты не требуют восстановления потерянных Excel-таблиц: исходники и их записи сохранены. Они требуют недостающих данных, явных бизнес-связей или новых расчётов. UI-исправления текущей задачи отражены в отдельном отчёте; они не закрывают перечисленные ограничения автоматически.

## Проверяемые исходники

- [Импорт Excel](../../app/importer.py): поля книг, категории и преобразование статусов.
- [Рабочая модель](../../app/workspace.py): сущности, ID-связи, версии, сохранение тарифов, права изменения, карты и расходы.
- [Статистика и сверка](../../app/analytics.py): формулы, пропуски, группы, ограничения распределения спутника.

- [ТрансТрейд](../../app/transtrade.py): текущие поля, `km=None`, сохранение исходного снимка и локальных категорий.
- [ГЛОНАСС: дневная история](../../app/monitoring_history.py): отдельные пробег/моточасы/расход, `hours=None`, объединение с Excel по машине/дню.

- [Календари плана](../../app/static/planviews.js): общий набор назначений для строк по маршруту/машине.
