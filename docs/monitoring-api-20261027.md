## Реализовано и проверено

- `app/monitoring.py`: только получение списка объектов и последних показаний; фиксированный HTTPS-домен, проверка TLS, без редиректов, ограничение размера ответа и таймауты.
- `POST /api/v3/vehicles/find` с `{}`: 19 объектов.
- `POST /api/v3/vehicles/getlastdata` с ID и `includeSensors: false`: показания 19 объектов.
- В приложении сохраняются ID/название/модель, состояние, скорость, время формирования и получения сообщения. Координаты, IMEI и телефоны не выдаются этим локальным API.
- Токен переиспользуется; при HTTP 401 выполняется один повторный вход. Между запросами пауза не менее 1,1 секунды. Обновления сериализованы, фоновое расписание не создавалось.
- `data/monitoring-credentials.json`, `data/monitoring-session.json`, `data/monitoring-vehicles.json`: вне Git, режим 0600. Снимок заменяется атомарно после успешного получения обоих наборов данных; ошибка оставляет прежний снимок.
- GET `/api/monitoring` и POST `/api/monitoring/sync`: руководитель; POST требует CSRF. Пароль и токен не передаются в браузер. Сырые сообщения ошибок провайдера не выдаются в интерфейс.
- Страница `/integrations/monitoring`; старый `/integrations/axenta` перенаправляет сюда. Старые результаты проверки axenta.cloud не применяются к новому серверу.
- Сохраняется интерфейс без верхней шапки на компьютере. Другие подключения и расчёты Excel не изменялись.

## Исторические показатели: граница готовности

Запрос `vehicles/mileageAndMotohours` за август сразу по 19 объектам превысил 60 секунд ожидания. Повторная диагностическая проверка по одному объекту за 1 августа 2026 прошла: HTTP 200, один суточный период, числовой пробег и моточасы. API возвращает моточасы в секундах. В запросе использовались локальные границы суток и `timezone: 3`; ответ повторяет границы без смещения.

История пробега, моточасов и топлива ещё не включена в расчёты и UI. Для неё требуется отдельная загрузка небольшими порциями с проверкой полноты, границ суток и соответствия объектов справочнику. Не подменять отсутствие данных нулями. Статус объекта из `vehicles/find` у всех 19 равен -1; для отображения используются состояния последних сообщений. «13 активных» из прежнего скриншота нельзя трактовать как административный статус или гарантию актуальности.
